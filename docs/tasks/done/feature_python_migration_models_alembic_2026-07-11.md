# FEATURE-003: planny-core — 9 SQLAlchemy models + Alembic migration

## Description

Implement all 9 SQLAlchemy 2.0 DeclarativeBase models mirroring the existing TypeORM entities exactly. Then capture the current database schema as an Alembic initial migration and disable TypeORM's `synchronize: true`.

## Context

Blueprint Section 4. TypeORM with `synchronize: true` has been auto-creating/modifying tables. There is no formal migration history. Before Python writes any data, we must: (1) define models matching the exact table/column names TypeORM generates, (2) generate an Alembic migration from the existing DB state, (3) stamp it as applied, (4) disable `synchronize: true` in TypeORM.

## Requirements

### Functional Requirements

**Core domain models (4):**
- `Project` (table: `project`): id, name, url, description, category, created_at, updated_at, relationships to issues/users
- `User` (table: `user`): id, name, email, avatarUrl, created_at, updated_at, project_id FK, relationships to comments/issues
- `Issue` (table: `issue`): id, title, type, status, priority, list_position, description, description_text, estimate, time_spent, time_remaining, reporter_id, project_id FK, created_at, updated_at, relationships to project/comments/users
- `Comment` (table: `comment`): id, body, user_id FK, issue_id FK, created_at, updated_at

**Jira integration models (5):**
- `WorklogSubmission` (table: `worklog_submission`)
- `WorklogSubmissionResult` (table: `worklog_submission_result`)
- `ExternalHoursDaily` (table: `external_hours_daily`)
- `DailyHours` (table: `daily_hours`)
- `TempoHoursDaily` (table: `tempo_hours_daily`)

**Junction table:** `issue_users_user` (issue_id, user_id) for the many-to-many Issue-User relationship

**Alembic:**
- Initialize `alembic init`, configure `env.py` to use SQLAlchemy models
- Run `alembic revision --autogenerate -m "initial_schema_from_typeorm"` against existing DB
- Run `alembic stamp head`
- Set `synchronize: false` in `api/src/database/createConnection.ts`

### Non-Functional Requirements

- Exact table and column names matching TypeORM autogenerated names (snake_case for SQLite/PG)
- Enum fields stored as VARCHAR, not native DB enums
- `updated_at` uses `onupdate=datetime.utcnow`
- Cascade deletes: Comment on Issue delete
- Use `selectinload` for eager loading relationships
- Implement SQLAlchemy event listener for `description_text` auto-generation from `description` (replaces TypeORM `@BeforeInsert` striptags)

## Current State

Reference files in `api/src/entities/` and `api/src/constants/`. TypeORM entities with decorators define the canonical schema. DB is the live source of truth.

### Key Decisions Made
- **DeclarativeBase with explicit Column**: Mirrors TypeORM decorators cleanly
- **VARCHAR for enums**: Avoids DB-level enum compatibility issues
- **Alembic --autogenerate**: Starts from existing DB, not from scratch
- **synchronize: false**: Prevents future TypeORM/Alembic conflicts
